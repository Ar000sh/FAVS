## Changed since the team version (for your info)
- **GroupMembershipView** (new «Read Model» in the Expense context). It is fed by GroupDomainEvents and passed into `Expense.record/correct/remove`, so Expense can check that payer and participants are members (R2/R3), that the group is open (R5) and that the editor is the recorder, the payer or an admin (R6).
- `Expense.record(...)` now takes everything Expense stores: groupId, title, paidBy, recordedBy, totalAmount, shares, splitStrategy.
- `InvitationDeclined` added to GroupDomainEvents (it was returned by `decline()` but missing from the list).
- `DebtForgiven` renamed to **`DebtWaived`**, to match `waive()`, `WAIVED` and `DEBT_WAIVED`.
- Settlement arrows now name their events, e.g. "publishes (MemberBalanceStatusChanged, AllBalancesSettled)". There is still one SettlementDomainEvents box.
- **Invitations go through the root Group** (decided 17.10). Rule 1 on DDD slide 67: changes only through the root, and outside code may not call inner entities directly.
  - New on Group: `acceptInvitation(InvitationId, UserId): MemberJoined` checks that the group is OPEN and the user is not yet a member, calls `invitation.accept()`, adds the Membership and publishes MemberJoined.
  - New on Group: `declineInvitation(InvitationId): InvitationDeclined`.
  - Invitation keeps `accept()` / `decline()`, but they now only change its status and no longer return events.
  - Before, `Invitation.accept()` returned `MemberJoined`, but it could not create the Membership, and Group had no method for joining.
- **Value objects for all types the model uses** (decided 17.10). Before, the model used these types but never defined them. Each is now a small «Value Object» box:
  - in the Group aggregate: `GroupName`, `Email`, `InvitationId`
  - in the Expense aggregate: `ExpenseId`, `ExpenseTitle`
  - in the GroupLedger aggregate: `EntryId`
  - in the SettlementPayment aggregate: `SettlementPaymentId`
  - in the shared kernel: `Currency`, as part of Money

  Slides:
  - **DDD slide 66**: "Use Value Objects instead of primitive types", with a code example that uses `EmailAddress`, `PhoneNumber` and so on instead of String.
  - **slide 68**: lists `GroupName` explicitly as a ShareWise value object, next to Money, ExpenseShare and Percentage.
  - **slide 64**: Money = `BigDecimal amount` + `Currency currency`.
  - **slide 65**: what a value object is (no identity, immutable, equal by its values).
- Presentation only: a dashed box per aggregate, colours by type, `name: Type` notation, `List<…>` generics.

## To decide together
1. **Auto-archive: yes or no?** The lecture leaves it open (DDD slide 7: "Is archiving automatic?"). Our requirements (L5) say yes.
   - If **yes**, Group needs a way to archive without an admin. For example `archiveWhenSettled()` on AllBalancesSettled, and only while the group is CLOSED_FOR_SETTLEMENT. Otherwise the group would also archive mid-trip when everyone happens to be at 0.
   - If **no**, an admin archives with `archiveGroup()`, which checks that every member has `hasZeroBalance`. Then Group no longer needs to subscribe to `AllBalancesSettled`.
   - The diagram currently keeps the team version: Group subscribes to AllBalancesSettled.
2. **`correct()` stays as the team had it** (amount + shares). Our journey J5 in `ShareWise_Requirements.md` also allows correcting the payer, so either we remove "payer" from J5 or we widen `correct()`. The slides only show `correct(newAmount)` (DDD slide 64).
3. **`waive()` / `DebtWaived`: left as the team had it, to discuss.**
   - It is a new feature: it isn't on the slides or in our requirements.
   - It sits on a SettlementPayment, so the debtor first has to record a payment that the creditor then waives. Waiving is about an open debt, not about a payment.
   - It has no exact meaning yet: does the creditor waive all of the debt or part of it, and what happens to both balances?
   - Options:
     - **(a)** Drop it for the MVP: remove `waive()`, `WAIVED`, `DebtWaived`, `appendDebtWaiver()` and `DEBT_WAIVED`.
     - **(b)** Keep it as a ledger command, e.g. `GroupLedger.waiveDebt(debtor, creditor, amount): DebtWaived`, plus a new rule in the requirements.
     - **(c)** Keep it as is and expect a question about it in P1.
4. **Small items:**
   - `createGroup()` has no parameters (name, currency, creator?).

## Decided, no action
- **No `date` on Expense.** It isn't on the slides: slide 64 gives Expense exactly id, groupId, paidBy, amount, splitStrategy, status.
- **Currency stays** (Group.currency, Money.currency, slide 64). We only dropped multi-currency and an extra currency check.
- **LedgerEntry stays an «Entity».** It is immutable, but each booking is its own fact that we need to refer to (audit, reversals). Slide 66 says entities are *often* mutable, not always.
- **No currency check.** One currency per group is our own simplification. The slides only have Money with Currency (slide 64).
